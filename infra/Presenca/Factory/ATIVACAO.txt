1. Pre-condicoes antes de instalar
Usar host Linux com systemd e Python 3, e versao revisada do repositorio completo
em /opt/yeshua-presenca/current (incluindo scripts/presenca e infra/private).
A fonte unica de configuracao continua sendo o arquivo privado existente
/root/YeshuaPrivate/production/credentials.json; o nome da pasta nao autoriza
apontar este ensaio para producao. Para outro perfil, preparar um drop-in que
substitua ExecStart com o caminho do MESMO loader/arquivo privado daquele ambiente.
Nao copiar chaves para unit files, ambiente de shell, Git ou este roteiro.

Configurar Apps.Presenca.Factory no arquivo privado:
  Enabled: booleano false inicialmente
  TenantId: ID positivo do tenant de homologacao
  IdentidadeId: identidade publicadora explicita, 64 hexadecimais
  Repository: repositorio GitHub publico autorizado, owner/repo
  Pages: 1 (limite de 100 registros por recurso; permitido 1 a 10)

Apps.Presenca.IngressUrl deve ser HTTPS e terminar exatamente em
/yapi/Presenca/Inbox/YeshuaModuleEvent. Usar ingress de HOMOLOGACAO isolado.
Shared.ModuleAuthentication.SharedKey e a chave existente, pelo loader unico.
API e Worker precisam do mesmo escopo de homologacao. O ator tecnico configurado
na autenticacao entre modulos precisa do vinculo Integrar na identidade indicada.
Admin generico/token ou primeiro chamador nao provisionam esse vinculo.

Ter aplicado as migrations do Studio em banco de teste e validado autorizacao,
recepcao, saga e persistencia antes de habilitar entrega automatica. O ensaio
padrao nao deve ter canais reais/autorizacoes editoriais pendentes. A recepcao

  install -m 0644 /opt/yeshua-presenca/current/infra/Presenca/Factory/yeshua-presenca-factory@.service /etc/systemd/system/yeshua-presenca-factory@.service
  install -m 0644 /opt/yeshua-presenca/current/infra/Presenca/Factory/yeshua-presenca-factory-collect.timer /etc/systemd/system/yeshua-presenca-factory-collect.timer
  install -m 0644 /opt/yeshua-presenca/current/infra/Presenca/Factory/yeshua-presenca-factory-deliver.timer /etc/systemd/system/yeshua-presenca-factory-deliver.timer
  systemctl daemon-reload
Enquanto Factory.Enabled nao for booleano true, os jobs informam disabled sem
criar spool nem fazer rede. StateDirectory prepara o spool persistente em
/var/lib/yeshua-presenca-factory com modo 0700; UMask=0077 protege os arquivos.
Nao usar o spool de outro ambiente/identidade para uma homologacao nova.

5. Habilitar agendamento depois do ensaio aprovado

  systemctl list-timers 'yeshua-presenca-factory-*'
Coleta: apos boot 5min e a cada 30min desde a conclusao, jitter ate 2min.
Entrega: apos boot 2min e a cada 1min desde a conclusao, jitter ate 10s.
Cada processo tem 120s/256M/25% CPU. Locks separados evitam sobreposicao da mesma
acao; indisponibilidade do GitHub nao impede escoar mensagens ja pendentes.
HTTP de entrega e idempotente por MessageId; timeout preserva .pending para replay.

6. Interromper agendamento sem apagar trabalho
  systemctl disable --now yeshua-presenca-factory-collect.timer yeshua-presenca-factory-deliver.timer
Configurar Factory.Enabled=false impede novos ciclos manuais/automaticos. Isso
nao cancela trabalho ja aceito na API/Worker. Nao apagar .pending/.sent/.retry,
recibos, versoes, auditoria ou releases para tentar recuperar uma falha.
Reprocessar falhas finais e callbacks pela Operacao; resultado externo incerto
exige reconciliacao, nunca reenvio cego. Limpeza/retencao exigem politica e ordem
explicitas; nenhum purge automatico foi incluido.
